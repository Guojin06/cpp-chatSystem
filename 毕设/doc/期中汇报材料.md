## 一、项目背景与概述

### 1.1 项目背景

本课题来源于学校与电力运维企业的合作课题。智能电表采集的电量数据、需量数据和变量数据是各类能耗管理平台和新能源调度装置正常工作的关键数据。

**课题要求**：
- 设计一套能够运行在嵌入式主机的软件
- 按计划通过MQTT协议驱动现场DTU发送下行指令
- 采集和解析电表DL/T 645协议数据
- 将电量数据（正向有功、反向有功、正向无功、反向无功等）和变量数据（最大需量、电压、电流、功率因数、有功功率、无功功率等）
- 转换为MQTT协议和HTTP协议，上传到公共物联网服务平台

### 1.2 项目名称

**基于DL/T 645协议的DTU物联网网关设计与实现**

### 1.3 核心功能

从电表读取DL/T 645协议报文，解析后：
- 存入本地SQLite数据库（断网保护）
- 发布到MQTT云端（数据上云）
- 提供HTTP API（前端展示）

### 3.2 DL/T 645协议详解

#### 3.2.1 协议帧格式

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│  字节位置  │  0   │   1-6    │  7   │   8   │   9   │ 10 ~(9+len) │ N-2  │  N  │
├─────────────────────────────────────────────────────────────────────────────────┤
│  含义      │ 帧头  │  地址域   │ 帧头  │ 控制码 │  长度  │   数据域     │ 校验  │ 帧尾  │
│  值        │ 0x68 │  6字节   │ 0x68 │  0x91  │ 0x0A  │   N字节     │ 求和  │ 0x16  │
└─────────────────────────────────────────────────────────────────────────────────┘
```

#### 3.2.2 关键字段说明

| 字段 | 长度 | 说明 |
|------|------|------|
| 帧头 | 1字节 | 固定值 0x68 |
| 地址域 | 6字节 | 电表编号（BCD码，低字节在前） |
| 控制码 | 1字节 | 0x91=读数据应答 |
| 数据长度 | 1字节 | 数据域字节数 |
| 数据域 | N字节 | 每字节发送时+0x33，接收后需-0x33 |
| 校验码 | 1字节 | 累加和低8位 |
| 帧尾 | 1字节 | 固定值 0x16 |

#### 3.2.3 示例报文解析

```
原始报文: 68 01 00 00 00 00 00 68 91 0A 33 33 34 35 55 35 45 33 88 43 08 16
           │                        │       │       │                  │     │
帧头 ──────┘                        │       │       │                  │     │
地址域(000000000001) ───────────────┘       │       │                  │     │
帧头 ───────────────────────────────────────┘       │                  │     │
控制码(0x91=读数据应答) ────────────────────────────┘                  │     │
数据长度(0x0A=10字节) ───────────────────────────────────────────────  │     │
数据域(需-0x33解码) ───────────────────────────────────────────────────┘     │
校验码 ───────────────────────────────────────────────────────────────────────┘
帧尾 ──────────────────────────────────────────────────────────────────────────┘

数据域解码(每字节-0x33):
33-33=00, 34-33=01, 35-33=02, 35-33=02, 55-33=22, 45-33=12, 33-33=00, 88-33=55, 43-33=10, 08-33=D5

数据标识: 00 01 02 02 (设备特定)
电压:     22 12 → BCD解码 → 22.12 ÷ 10 = 22.2V
电流:     00 55 → BCD解码 → 55.00 ÷ 100 = 0.55A
电能:     10 D5 → BCD解码 → D510 ÷ 100 = 10.55kWh
```

#### 3.2.4 帧合法性验证（4道门卫）

```cpp
bool DLT645Parser::validateFrame(const std::vector<uint8_t>& frame) const {
    // 检查1：最小长度（帧头+地址+帧头+控制码+长度+校验+帧尾 = 12字节）
    if (frame.size() < 12) return false;
    
    // 检查2：帧头帧尾是否符合645协议规定
    if (frame.front() != 0x68 || frame[7] != 0x68 || frame.back() != 0x16) return false;
    
    // 检查3：数据域长度字段与实际帧长是否一致
    if (frame.size() != 12 + frame[9]) return false;
    
    // 检查4：重新计算校验码，与报文中携带的校验码对比
    return calculateChecksum(frame) == frame[frame.size()-2];
}
```

### 4.2 DL/T 645协议解析器 (dlt645_parser.cpp)

解析流程：
1. 验证帧合法性（4道门卫）
2. 提取基本信息（电表编号、时间戳）
3. 数据域减0x33还原
4. 切片取值并BCD解码

```cpp
std::optional<MeterReading> DLT645Parser::parseFrame(const std::vector<uint8_t>& frame) const {
    if (!validateFrame(frame)) return std::nullopt;

    MeterReading reading;
    reading.meterId = parseMeterId(frame);
    reading.timestamp = currentTimestamp();

    // 数据域减0x33还原
    const std::size_t dataLen = frame[9];
    std::vector<uint8_t> data(frame.begin() + 10, frame.begin() + 10 + dataLen);
    for (auto& byte : data) {
        byte = static_cast<uint8_t>(byte - 0x33);
    }

    // BCD解码
    reading.voltage = decodeBcdValueReversed({data[4], data[5]}, 10.0);    // 22.2V
    reading.current = decodeBcdValueReversed({data[6], data[7]}, 100.0);   // 0.12A
    reading.activeEnergy = decodeBcdValueReversed({data[8], data[9]}, 100.0); // 10.55kWh

    return reading;
}
```

### 4.3 串口读取器 (serial_reader.cpp)

使用Linux termios API配置串口，逐字节读取直到找到完整帧。

```cpp
bool SerialReader::open() {
    fd_ = ::open(port_.c_str(), O_RDWR | O_NOCTTY | O_NDELAY);
    if (fd_ < 0) return false;

    struct termios tty;
    tcgetattr(fd_, &tty);
    
    cfsetispeed(&tty, B9600);
    cfsetospeed(&tty, B9600);
    tty.c_cflag = B9600 | CS8 | CLOCAL | CREAD;  // 8N1
    tty.c_cc[VMIN] = 0;
    tty.c_cc[VTIME] = 10;  // 1秒超时
    
    tcsetattr(fd_, TCSANOW, &tty);
    return true;
}

std::vector<uint8_t> SerialReader::readFrame(int timeoutMs) {
    std::vector<uint8_t> buffer;
    bool frameStarted = false;
    
    while (elapsed < timeoutMs) {
        int n = ::read(fd_, &byte, 1);
        if (n > 0) {
            if (!frameStarted && byte == 0x68) {
                buffer.clear();
                buffer.push_back(byte);
                frameStarted = true;
            } else if (frameStarted) {
                buffer.push_back(byte);
                if (byte == 0x16 && buffer.size() >= 12 && buffer[7] == 0x68) {
                    return buffer;  // 完整帧
                }
            }
        }
    }
    return {};
}
```

### 4.4 SQLite数据库操作 (db_handler.cpp)

使用prepare/bind机制安全地写入数据，支持批量操作。

```cpp
bool DbHandler::insert(const MeterRecord& record) {
    sqlite3_stmt* stmt;
    sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
    
    sqlite3_bind_text(stmt, 1, record.meterId.c_str(), -1, SQLITE_STATIC);
    sqlite3_bind_text(stmt, 2, record.timestamp.c_str(), -1, SQLITE_STATIC);
    sqlite3_bind_double(stmt, 3, record.voltage);
    sqlite3_bind_double(stmt, 4, record.current);
    sqlite3_bind_double(stmt, 5, record.activeEnergy);
    sqlite3_bind_double(stmt, 6, record.powerFactor);
    sqlite3_bind_text(stmt, 7, record.rawFrame.c_str(), -1, SQLITE_STATIC);
    sqlite3_bind_int(stmt, 8, record.uploaded);
    sqlite3_bind_int(stmt, 9, record.uploadRetry);

    bool success = (sqlite3_step(stmt) == SQLITE_DONE);
    sqlite3_finalize(stmt);
    return success;
}
```

## 八、答辩问答准备

### Q1: 为什么选择MQTT协议？
> MQTT是轻量级物联网通信协议，专为低带宽、高延迟、不稳定的网络环境设计，适合DTU设备。

### Q2: 断网了怎么办？
> 使用SQLite本地存储数据，网络恢复后从数据库读取未上传记录重新发送。

### Q3: 645协议怎么解析？
> 帧头(0x68) → 地址域(6字节) → 帧头(0x68) → 控制码 → 长度 → 数据域(每字节-0x33) → 校验码 → 帧尾(0x16)

### Q4: 为什么手动实现MQTT？
> 避免引入第三方库依赖，减少交叉编译复杂度，代码可控可学习。

### Q5: 如何保证数据可靠性？
> 1) 帧校验码验证 2) SQLite本地存储 3) 未上传记录标记 4) 重传机制
