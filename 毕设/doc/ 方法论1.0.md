## 1. 通用学习方法论（所有主线通用）

### 1.1 工程思维：MVP + 小闭环

- **MVP 原则**：任何大目标都要先收敛成「7～21 天可完成的版本」，避免无上限计划。
- **每个模块的闭环模板**：
  1. 明确当前模块的**可见终点**（例如：聊天室支持多客户端广播 + 简单日志）。
  2. 快速浏览 20～30 分钟相关资料/课程，只找「整体框架」和「易踩坑」。
  3. 集中 1.5～3 小时写代码/做题/推导，进入深度专注区。
  4. 做最小自测/压测：跑 demo / 写几个样例 / 打 log 看状态。
  5. 在 XMind + 语雀里各产出一个小节点/小卡片，记录本轮收获和坑。

### 1.2 工具分工：XMind / 语雀 / AI

- **XMind = 唯一知识树**：
  - 负责「结构」与「高浓度摘要」。
  - 每个节点只有 3～8 行自己的话：模型、关键点、常见坑、代表题/例子。
  - 大类：算法、DP、计网、OS、Linux、Redis、英语、长期规划等。

- **语雀 = 小卡片 + 长文仓库**：
  - 记录具体推导、图、例子、长篇题解、专题方法论文章。
  - 每个卡片控制在 300～800 字优先，超过就拆分。

- **AI = 助教，不是作者**：
  - 流程：**先自己写 → 再让 AI 提问/补充/检查 → 再由自己改回去**。
  - AI 适合做的事：
    - 帮忙查漏补缺（「我这个总结有没有漏掉常见坑？」）；
    - 帮做对比/类比（「这题和 322/377 有啥共同点？」）；
    - 帮压缩/润色已有内容。

### 1.3 一天内部结构原则

- **大块深度（≥2h）**：只留给项目 / Redis / 计网OS 中的重难点。
- **小块稳定（0.5～1h）**：算法、六级、计网OS/Redis 的「单知识点闭环」。
- **每天结束前 5～10 分钟**：写 3 行复盘：
  - 今天最重要的 1～3 个结果是什么？
  - 哪个时间块效率最低？
  - 明天第一块时间想先攻哪条线？

### 1.4 XMind 与手写/演算的分工

- **XMind 适用场景（看森林）**：
  - 新开一门课 / 一大章 / 一类专题时：先画出整体结构（如算法总图、DP 分类、计网分层等）。
  - 同类内容积累到 3～5 个例子后：用一个节点抽象出「模型 / 通用套路 / 易错点」，挂上代表题或例子。
  - 项目中新增模块/子系统时：画出模块关系、数据流、关键约束，作为后续讲项目和维护的总图。

- **手写/演算适用场景（啃树根）**：
  - 推不顺 / 老记不住 / 老出错的地方：
    - 如复杂 DP 转移、图论算法流程、滑动窗口边界、锁/并发顺序等，在纸上带小样例推一遍表/栈/队列/状态。
  - 需要「干跑一遍」的流程：
    - 如 TCP 三次握手/四次挥手状态机、进程切换流程、页面置换算法、Redis 跳表搜索路径等，用时间轴/状态图手画出来。
  - 以后要现场讲给别人听的内容：
    - 准备面试要讲的代表题、项目核心流程、专题方法论时，先在纸上写提纲 + 画图，模拟讲一遍，找出卡壳点。

- **二者关系**：
  - XMind 负责「长期索引和结构压缩」，是以后复盘和扩展的入口；
  - 手写/演算负责「当下深度理解和思维肌肉训练」，是把结论变成自己推导能力的过程；
  - 判断规则：
    - 以后会经常回顾/扩展 → 上 XMind；
    - 现在推不顺/记不牢/要讲给别人 → 至少手写/演算一遍。

## 2. 日计划模板（高配版 & 低配版）

### 2.1 高配版（目标 9～10 小时有效学习）

> 用于状态正常或进行「清华强度实验周」时。

- **Block1（09:00–11:30，2.5h）——项目 Deep Work**
  - 只做一件事：聊天室 / 内存池 / 毕设的某个小模块（网络 IO、连接管理、协议解析、内存池分配策略等）。
  - 规则：关手机，最少 2×50 分钟番茄，中间休 10 分钟。

- **Block2（11:30–12:30，1h）——算法 + XMind/DP**
  - 30–40 min：1～2 题中等题（跟当前专题对应）。
  - 20–30 min：1 个旧题或核心 DP 题，在 XMind 写 3～8 行自己的摘要。

- **午休（12:30–14:00）**：吃饭 + 简单休息。

- **Block3（14:00–15:30，1.5h）——计网/OS + Linux（项目驱动）**
  - 选一个和当天项目强相关的知识点（如 TCP 三/四次握手、阻塞/非阻塞、epoll 原理、进程/线程等）。
  - 30–40 min：看书/视频/博客一小节。
  - 40–60 min：XMind 建节点 + 语雀写 300～500 字小卡片。

- **Block4（15:45–17:15，1.5h）——Redis / 或 第二个基础知识点**
  - 两种日型轮换：
    - Redis 主角日：1h 看一块原理/源码/应用 + 0.5h XMind + 问答；
    - 计网/OS 主角日：同样逻辑，换成 OS/网络主题。

- **晚饭（17:15–19:00）**。

- **Block5（19:00–20:00，1h）——六级固定块（仅未来约 20 天）**
  - 20 min 听力；30 min 阅读；10 min 作文/翻译模板或背句子。
  - 到点就停，不侵占其他主线时间。

- **Block6（20:10–22:10，2h）——机动强化块**
  - 根据当天进度从「项目 / 算法 / 基础 / Redis」里选 1 个主角：
    - 项目不够 → 再写 1.5h 代码 + 0.5h 记要点；
    - 算法虚 → 再做 1～2 题 + XMind；
    - 基础/Redis 卡住 → 再啃 1 小知识点 + 输出。

- **睡前 10 分钟**：打分（执行度/专注度/状态），更新明日优先级。

### 2.2 低配版（情绪/体力低时的「最低不间断版本」）

> 用于状态很差、自我怀疑严重的日子，只要求「主线不断」，不要求高强度。

- 项目：30–40 min
  - 修 1 个小 bug / 写 1 个小函数 / 补一小段日志或流程图。
- 算法：30 min
  - 1 题简单/中等，允许看题解后重写；
  - 若实在做不动新题，重写一题旧题代码 + XMind 回忆。
- 基础（计网/OS/Redis 三选一）：30 min
  - 1 个知识点闭环（看 1 小节 + XMind 3～5 行摘要）。
- 六级（在考试前 20 天内）：20–30 min
  - 听力或阅读的一小段。
- 复盘：5 min
  - 写一句话：「今天状态一般，但主线没有断。」

只要完成低配版，这一天在长期大目标上的贡献就不是 0，可以降低情绪波动对执行的破坏。

## 3. 项目 / 毕设 学习方法

### 3.1 项目定位与拆分

- 当前主项目：
  - C++ 分布式聊天室（基于 epoll、网络 IO、多客户端支持、协议设计等）；
  - 内存池（为后续高并发/分配优化做准备）；
  - 毕设（Python + Vue 为主，可视为工程综合项目）。

- 原则：
  - 任何需求必须拆成「可以在 3～7 天内完成的子模块」，避免「巨无霸任务」。
  - 每个子模块至少包括：功能、简单压测、日志、配置、README 一句话说明。

### 3.2 单个模块的工作流

1. **定义场景和边界**：
   - 这次要完成的功能是什么？输入/输出/异常场景各是什么？
2. **画图**：
   - 在纸上或 XMind 画数据流图/状态机（连接创建/关闭、消息流转等）。
3. **最少看课/文档（20～30 min）**：
   - 只取框架和典型坑点，不追求「完全看完」。
4. **集中编码（≥90 min）**：
   - 只开编辑器和必要的手册/API 文档，不看杂信息。
5. **自测/压测**：
   - 多客户端连接、发消息、模拟断连/异常；
   - 记录观察到的瓶颈或异常行为。
6. **输出总结**：
   - XMind：为本模块加一节点（模块名 + 关键设计点）；
   - 语雀：写 300～800 字的简要记录（问题 → 方案 → 坑 → 下一步）。

### 3.3 项目与基础课的联动

- 当项目中遇到某个概念（如「半连接队列」、「阻塞/非阻塞 IO」）：
  - 当天或次日，在计网/OS XMind 里创建对应节点；
  - 用项目中的真实场景来解释概念，而不是只背定义。

## 4. 算法 / DP 学习方法

### 4.1 总原则

- 目标：为春招面试 + 未来 826 打底。
- 配比：
  - **70% 时间：刷新题（覆盖常见题型）**；
  - **30% 时间：整理旧题/专题方法论（主要在 XMind 中完成）**。
- 载体策略：
  - **XMind = 算法知识的唯一主视图**；
  - Markdown/博客/AI 题解 = 参考资料。

### 4.2 算法 XMind 结构（总图）

建议顶层结构如下（可后续微调）：

- 数组 / 字符串
- 链表 / 哈希
- 栈 / 队列 / 单调栈 / 单调队列
- 双指针 / 滑动窗口
- 二分 / 排序 / 前缀和 / 差分
- 树 / 二叉树
- 图（DFS / BFS / 拓扑 / 最短路基础）
- 贪心
- 回溯 / 搜索
- DP
  - 背包（0-1 / 完全 / 多重 / 二维费用 / 方案数/最值/可达性）
  - 子序列 DP（LIS / LCS / 编辑距离 / 子序列匹配等）
  - 区间 DP
  - 树形 DP
  - 状压 DP
  - 其他（数字 DP / 博弈等，先留坑）

每个节点下再挂代表题和 3～8 行摘要。

### 4.3 单道题的 XMind 节点模版

每个代表题在 XMind 中建议包含：

- **标签**：题型 + 专题，如 `[完全背包·最小值] LC279 完全平方数`。
- **问题模型**：1 句话；
- **状态定义**：`dp[...]` 的物理含义；
- **转移 + 初始化 + 遍历方向**：各 1 句，说明「为什么这样做」；
- **坑点 / 变体**：2～3 点（例如可达性、INF 处理、顺序问题）；
- **关联题**：列出 1～3 个同类题，仅题号即可。

### 4.4 每日算法流程（约 1 小时）

1. **旧题/DP 精炼（20～25 min）**
   - 从预先选好的「核心 DP 题集」中选 1 题；
   - 不看旧笔记，先在 XMind 用 3～8 行写出自己的总结；
   - 再对照 AI/旧题解，检查有无漏点，必要时补充 1～2 行。

2. **新题实战（30～40 min）**
   - 按当前「周专题」（如背包、子序列、数组双指针等）选 1～2 题中等题；
   - 独立思考 ≤15 min，超过就看少量提示再做；
   - 至少给其中 1 题在 XMind 或草稿中写 3～5 行思路。

### 4.5 周节奏与周赛

- 每周选择 1 个主专题（如：背包 → 子序列 → 树/图 → 二分/贪心…）。
- 周内：
  - 每天旧题/XMind 部分优先选这个专题的代表题；
  - 新题也尽量围绕该专题。
- 周末（1.5～2h）：
  - 上半场：参加一次周赛或做一场往期周赛作为模拟（1～1.5h）；
  - 下半场：写一份「本周专题方法论小结」（可写在语雀）：
    - 有哪些模型；
    - 常用状态/转移套路；
    - 初始化/遍历的共性；
    - 本周代表题列表。

### 4.6 DP 阶段目标 v1（约 21 天）

- 完成 DP XMind 骨架：背包 / 子序列 / 区间 / 树形 / 状压 等二级结构。
- 选出 ≈32 道核心 DP 题，每题在 XMind 上有自己的摘要节点。
- 同期新刷 40～60 道题（不全是 DP，可包含数组/双指针等）。
- 至少完成 1～2 篇 DP 方法论长文（如「背包篇」「子序列篇」）。

## 5. 计网 / 操作系统 / Linux 学习方法

### 5.1 项目驱动选题

- 每天优先从「当天项目中实际用到/困惑的点」中选择 1～2 个知识点。
- 示例：
  - 项目在写 socket/epoll → 选 TCP 握手挥手、阻塞/非阻塞 IO、epoll 原理；
  - 在做多线程/内存池 → 选进程/线程区别、堆栈管理、锁/竞态等。

### 5.2 单知识点闭环模板

1. **预览（5 min）**：看章节标题/目录，知道此知识点位于哪一章、和谁相关。
2. **理解（20～30 min）**：看书/视频/博客：
   - 尝试画出流程图或状态图；
   - 记录关键术语（如 TIME_WAIT、半连接队列、上下文切换等）。
3. **三问检验（10 min）**：
   - 它是什么？（一句话定义 + 场景）
   - 为什么要这样设计？（如为什么需要 TIME_WAIT）
   - 常见坑/混淆点？
4. **联系项目（10–15 min）**：
   - 在当前项目中，这个概念出现在哪？
   - 如果处理不好，会出现什么 bug 或性能问题？
5. **输出卡片（15–20 min）**：
   - XMind 新增节点：关键词 + 3～5 行总结；
   - 语雀写 300～500 字小卡片（含 1 个小图或伪代码）。
6. **延迟回忆（5 min，1～2 天后）**：
   - 不看笔记，尝试口头/纸上复述核心内容，再对照修正。

### 5.3 长期目标 v1

- 约 6～8 周内完成：
  - 计网 ≈20 个节点（从应用层到链路层的典型概念/机制）；
  - OS ≈20 个节点（进程/线程/调度/内存/文件系统/同步等）；
  - Linux 命令/工具与 OS 概念建立映射（如 `ps/top/strace` 对应进程管理）。

## 6. Redis 学习方法

### 6.1 结构划分（XMind）

- 数据结构：String / List / Hash / Set / ZSet + 底层实现（SDS、linkedlist/quicklist、hashtable、skiplist 等）。
- 持久化：RDB / AOF / 混合持久化。
- 主从 & 哨兵。
- 集群。
- 缓存设计问题：穿透 / 击穿 / 雪崩、热点 key、分布式锁等。

### 6.2 每日小闭环（约 1.5～2h）

1. 40～60 min：看对应模块的课程/文档/源码讲解；
2. 30～40 min：整理 XMind 节点 + 语雀卡片：
   - 结构图/流程图；
   - 3～5 条关键结论；
   - 2～3 个常见面试问法；
3. 20～30 min（可选）：
   - 写/跑一个小 demo（本地 Redis + C++ 客户端），练习常用命令/模式。

### 6.3 与项目结合

- 后续为聊天室/项目增加 Redis 相关功能，如：
  - 会话信息缓存；
  - 在线用户列表；
  - 简单排行榜/计数器等。
- 在简历中将 Redis 作为「已在真实项目中使用过的组件」来讲。

## 7. 六级轻量学习方法

> 约未来 20 天内有效，之后可收缩为维护时间。

- 每天固定 0.5～1 小时，不允许侵占主线（项目/算法/基础）时间。
- 单次结构建议：
  - 听力：20 min（真题一部分，纠正发音/听不出的位置）；
  - 阅读：30 min（1～2 篇 + 对答案 + 标注错因类型：生词/长难句/粗心）；
  - 模板/句型：10 min（背/默写 3～5 句作文/翻译高频句式）。
- 目标：通过 5～8 套真题的实战，恢复/建立考试手感，而不是追求“全系统学完英语”。
